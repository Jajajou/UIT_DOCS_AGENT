## Problem Statement
The `web/` implementation is currently co-located with the core LangGraph AI backend. In order to focus purely on the AI/thesis aspects, the repository needs to be cleanly separated so a collaborator (HL) can take over web development without local development blockers.

## What Makes This Cool
The velocity multiplier of parallelizing work without stepping on each other's toes. It turns a solo academic project into a frictionless, multi-developer engine. A clean API contract enables the frontend and backend to evolve completely independently.

## Constraints
- Must unblock collaborator (HL) immediately.
- Minimal overhead managing cross-repo dependencies.
- Eventual target: both deployed independently to Cloud Run for the thesis demo.

## Premises
1. **Clear API Contract:** The boundary between the two repos must be a strictly defined API over the network.
2. **Independent Deployment:** The AI server will be deployed and scaled completely independently of the Web App via Cloud Run.
3. **Organizational Driver:** Handoff is the main driver for the split, prioritizing development velocity.

## Approaches Considered
### Approach A: The Mock API Split (Minimal Viable)
Move `web/` to a new repo. Define the API payload, deploy a mock server to Cloud Run by Sunday, and hand the URL to HL. Build the real LangGraph logic at your own pace.
### Approach B: The Monorepo Compromise
Keep `web/` inside `UIT_DOCS_AGENT` but use strict workspace boundaries and deploy independently.
### Approach C: The Real-Time Dashboard (Ideal/Creative)
Split the repos, but design the contract entirely around Server-Sent Events (SSE) to visualize the AI's thought process.

## Recommended Approach
**Approach A: The Mock API Split**
Selected by the user because it immediately unblocks the collaborator (HL) and physically enforces the separation of concerns needed to focus on the thesis logic.
