## Problem Statement
The thesis project requires the LangGraph AI server to be deployed online so it can be demonstrated to peers and advisors smoothly, but it needs to be as close to free as possible.

## Constraints
- **Cost:** Must be 100% free (or extremely close).
- **Reliability:** Must not OOM during the demo and must avoid 504 Gateway Timeouts from cold starts.
- **Latency:** Needs fast RAG pipeline execution, avoiding cross-datacenter compounding latency.

## Recommended Approach
**Approach A: Local Docker + Cloudflare Tunnel (100% Free)**

*Pivot Rationale:* During the Engineering Review, the outside voice identified fatal flaws with Approach B (Frankenstein Free Tier):
1. **Fatal OOM Risk:** 512MB RAM on Render is insufficient for LangGraph/RAG, leading to instant OOM kills.
2. **Cold Start Death:** Render spins down after 15m; heavy Python boot times guarantee 504 Gateway Timeouts on the first query.
3. **Network Latency Nightmare:** Splitting compute and state across 4 different free-tier datacenters creates compounding latency for sequential RAG pipelines.

By running the entire stack (API, Postgres, Qdrant, Redis) locally via Docker Compose and exposing it via a Cloudflare Tunnel (`cloudflared`), we achieve 0ms database latency, utilize the laptop's robust RAM to avoid OOMs, and bypass cold starts entirely.

## Success Criteria
The web frontend successfully connects to the tunneled LangGraph API, queries the thesis knowledge base, and returns answers reliably without timeouts or OOM errors.

## Distribution Plan
- **Infrastructure:** Local Docker Compose.
- **Exposure:** Cloudflare Tunnel (`cloudflared`) routing public HTTPS traffic to local port 8000.
- **CI/CD:** Not applicable (runs locally on the presenter's machine).

## Next Steps
1. Install `cloudflared` on the host machine.
2. Configure a tunnel to route to `localhost:8000` where the LangGraph API runs.
3. Update the frontend `.env` to point to the new Cloudflare Tunnel URL.
